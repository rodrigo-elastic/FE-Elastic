# i18n audit - Demo Data, Workflow Demo, FE Brain

filename: i18n.md
description: Audit of internationalization coverage for the three new FE Copilot pages (Demo Data, Workflow Demo, FE Brain). Battlecards page does not exist yet at the time of this audit and is therefore not in scope.
Author: Rodrigo Careaga
Date: 03-05-2026

## Summary

The base i18n module (`frontend/assets/js/i18n.js`) is a flat dictionary keyed by language code (`en`, `es`, `ja`, `de`, `fr`) with helpers `applyI18n()`, `renderLangPicker()`, `t()`, `getLang()`, `setLang()`, and `claudeLanguageName()`. Translation is wired by walking the DOM for `data-i18n`, `data-i18n-placeholder`, and `data-i18n-title` attributes.

Battlecards landed mid-audit. Its dictionary keys (10 keys per language, namespace `bc.*` plus `topbar.tag.battlecards`) were added to all five languages so the page becomes wireable in a follow-up. The `frontend/battlecards.html` markup itself was NOT modified because the page is outside the file-ownership scope of this audit.

Before this audit:
- `frontend/index.html`, `frontend/meeting.html`, and `frontend/tools.html` were fully translated and called `applyI18n()` + `renderLangPicker()` from their respective JS bundles (`app.js`, `meeting.js`, `tools.js`).
- `frontend/demo-data.html`, `frontend/workflow-demo.html`, and `frontend/fe-brain.html` had a `lang-host` div but zero `data-i18n` attributes and zero boot wiring. The language picker did not render and switching language had no effect on these pages.

After this audit:
- All three new pages have the language picker rendered, all user-facing chrome marked with `data-i18n`, and a small inline boot script that calls `applyI18n()` plus `renderLangPicker()` after `DOMContentLoaded`. Their dedicated bundles (`demo-data.js`, `workflow-demo.js`, `fe-brain.js`) were intentionally NOT modified per the file-ownership rules; the inline boot avoids touching them.

## Strings added per language

A total of **76 new keys** were added to each of the 5 languages (`en`, `es`, `ja`, `de`, `fr`), so **380 new translations** in total. Each language now exposes 143 keys (verified via parity check).

Namespaces:
- `topbar.tag.*` (4 keys): per-page tag-line in the brand bar (demo, workflow, brain, battlecards).
- `dd.*` (15 keys): Demo Data hero, scenario card buttons, status pills, toast copy.
- `wf.*` (24 keys): Workflow demo hero, four numbered flow steps, three card sections, six action buttons, fires panel.
- `fb.*` (19 keys): FE Brain hero, three pills, suggested-prompt chips, composer placeholder, send/clear buttons, hint text, empty-state.
- `bc.*` (10 keys): Battlecards hero, two pills, search placeholder, grid loading state, modal close. Dictionary-only (markup not yet wired - see TODO).

Workflow page strings are intentionally split into prefix/suffix fragments around inline `<code>` elements (e.g. `wf.step2.prefix`, `wf.step2.suffix`) to keep code identifiers untouched while allowing the surrounding prose to translate.

The `dd.*` action keys (`dd.btn.seed`, `dd.btn.dashboard`, `dd.btn.cleanup`, `dd.status.*`, `dd.toast.*`) are seeded for the dynamic JS to consume via `t()`. ## Tone notes per language

- **English**: existing copy preserved as the canonical form. Kept ASCII punctuation only (no em/en dashes anywhere).
- **Spanish**: LATAM voseo to match the rest of the dictionary (`Usalos`, `necesitás`, `preguntale`). Loanwords kept untranslated where they are domain idioms in the Elastic / SaaS / FE community: `dashboard`, `cluster`, `index`, `webhook`, `connector`, `trigger`, `workflow`, `mocks`, `discovery`, `Lorem ipsum`. RAG and ILM kept as initialisms.
- **Japanese**: 敬語 for headers, status pills and buttons (`ご活用ください`, `お尋ねください`, `準備が完了しました`), neutral です/ます for body copy. Domain terms in katakana (`ダッシュボード`, `クラスタ`, `エージェント`, `トランスクリプト`, `ワークフロー`, `コネクタ`, `Webhook`). Code identifiers (`fec-transcript-inbox`, `.es-query`, `.webhook`, `/api/v1/workflows/triggered`, `ELSER`, `ES|QL`) untouched.
- **German**: Sie form throughout for a professional/sales context (`Setzen Sie sie ein`, `Fragen Sie die Docs`, `Wählen Sie oben`). Compound nouns used where natural (`Demo-Daten`, `Discovery-Transkript`, `Webhook-Auslösungen`). Anglicisms kept where standard in the German tech industry: `Dashboard`, `Cluster`, `Workflow`, `Webhook`, `Connector`, `Mocks`, `Live`, `Schedule`.
- **French**: vous form throughout (`Posez n'importe quelle question`, `Choisissez une requête`, `Utilisez-les en démo`). Light franglais where natural and standard at Elastic France: `dashboard`, `cluster`, `workflow`, `webhook`, `connector`, `mocks`, `live`. Octets + Go used over bytes/GB only where it fits the existing key (kept GB to mirror `200 GB/day`).

## Verification

- `grep -c 'data-i18n' demo-data.html` -> 4 elements (hero title 2, lede, loading state). Tag in topbar also tagged: 5 with the topbar tag attribute. The dynamic grid is JS-rendered (see TODO).
- `grep -c 'data-i18n' workflow-demo.html` -> 20 elements covering hero, 4 flow steps with code-tag splits, 3 card titles, 6 buttons, fire note, status loading, fires panel.
- `grep -c 'data-i18n' fe-brain.html` -> 17 elements covering hero, 3 pills, 5 suggested chips, composer placeholder + 2 buttons (clear has both text and title attrs), hint paragraph, empty state.
- All 3 pages have `<div class="lang-host" id="lang-host"></div>` in the topbar (pre-existed).
- All 3 pages now boot i18n via an inline IIFE that runs on `DOMContentLoaded` (or immediately if the document already loaded) and calls both `applyI18n()` and `renderLangPicker()`.
- `i18n.js` parses cleanly under JavaScriptCore (osascript -l JavaScript). Braces and brackets balance.
- Key parity check: each of the 5 language blocks has exactly 143 keys. No language is missing or has extra keys versus English (canonical).
- em/en dash audit: zero em (U+2014) and zero en (U+2013) dashes across the four touched files plus this audit doc.
